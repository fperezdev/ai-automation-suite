🦷 El caso de referencia

Clínica Dental Sonrisa Ñuñoa — Santiago, Chile · 3 odontólogos + 2 asistentes. Dolor: WhatsApp a mano todo el día, facturas de insumos tipeadas a planilla, consultas de noche sin responder, cero seguimiento a pacientes nuevos.

Antes (a mano)Después (con la suite)
Respondían el WhatsApp uno por uno; los mensajes de la noche se perdíanM1 — asistente 24/7 que responde solo y deriva a una persona cuando corresponde
Cada factura de insumos se copiaba a mano a una planillaM2 — lee el PDF, valida los totales y registra el gasto solo
Las consultas de la web quedaban sin seguimientoM3 — las califica y redacta el email de seguimiento
El personal preguntaba todo por internoM4 — agente de soporte interno con la FAQ del equipo

La suite es genérica: los 4 módulos sirven para cualquier PyME (retail, servicios, salud, gastronomía). La clínica es solo el ejemplo concreto.

🧩 Los 4 módulos

El módulo 1 es la pieza estrella: corre sobre WhatsApp real con la Cloud API oficial de Meta y es el único con RAG.

MÓDULO 01

Asistente de WhatsApp con RAG

WhatsApp Cloud API → recuperación por relevancia (TF-IDF + coseno) sobre la base de conocimiento del negocio → respuestas fundamentadas + derivación a humano.

MÓDULO 02

Automatización de facturas

Sube un PDF → el LLM extrae los campos → reglas de negocio validan → planilla + reporte HTML con badge PASS/REVIEW.

MÓDULO 03

Captación de pacientes / leads

Formulario → enriquecimiento (fetch del sitio) + scoring con IA HOT WARM COLD → registro + borrador de seguimiento.

MÓDULO 04

Agente de soporte interno

Webchat que responde con los datos del negocio y deriva a una persona con el transcript completo cuando debe.

🏗️ Arquitectura

RAG sin vector DB: el módulo 1 recupera con TF-IDF + similitud coseno en un Code node (exacto y sin dependencias para bases chicas; se cambia por embeddings + pgvector cuando la base crece). El LLM redacta, pero el contenido lo aporta la base de conocimiento: si algo no está, no lo inventa y deriva.

🚀 Quickstart — un comando, sin API keys

El repo trae un LLM mock determinista (solo stdlib). Para usar un modelo real (DeepSeek, OpenAI, Groq, Ollama…) cambiás una URL.

$ make up      # levanta n8n (:5688) + el LLM mock
$ make demo    # maneja los workflows por HTTP real y verifica

🧰 Stack y qué demuestra

n8n

Webhooks (GET+POST), Code nodes, Data Tables, IF, HTTP Request, respondToWebhook.

RAG

TF-IDF + coseno, chunking, grounding y trazabilidad de fuentes.

LLM

Salida JSON estructurada, prompt engineering, guardas deterministas de tono.

WhatsApp Cloud API

Verificación de webhook, parseo de payloads, envío por Graph API, handoff humano.
